Ship like a team of eight.

Not one agent doing everything.

crew sets up a real agent team in your repo: an orchestrator and seven roles with clear ownership, written briefs, independent review and human gates. Nobody approves their own work.

            The problem
            

              One agent that scopes, builds, tests and approves its own work will tell you it is
              done.
            

          

          

            

              01
              
No roles

              

                The same session decides what to build, how it looks and whether it works. Every
                concern gets a fraction of the attention.
              

            

            

              02
              
No source of truth

              

                Decisions live in chat history. Tomorrow's session re-litigates yesterday's scope
                because nothing was written down.
              

            

            

              03
              
No independent review

              

                "Tests pass" from the author is a claim, not evidence. You become the only reviewer
                of everything.
              

            

          

        

      


      

        

          

            

              How it works
              
Plain files Claude Code already understands.

            

            

              No runtime, no server, no lock-in. crew writes Markdown into your repo and checks it
              stays consistent. Every iteration follows the same five steps.
            

          

          

            
    
              
  1. 
                
    Goal. You say what you want and why.
    
              
    2. 
              
  2. 
                
    
                  Brief.
                  The orchestrator writes a brief with acceptance criteria and an out-of-scope
                    list.
                
    
              
    3. 
              
  3. 
                
    
                  Work.
                  The owning role does it and ends with a fixed handoff block.
                
    
              
    4. 
              
  4. 
                
    
                  Review.
                  A different role verifies with evidence. FAIL goes back to the author.
                
    
              
    5. 
              
  5. 
                
    
                  Gate.
                  Scope, design, production, ship and publish stop for your explicit yes.
                
    
              
    6. 
            

          

          

            

              docs/AGENT_TEAM.md
            

            

          

        

      


      

        

          

            The team
            
Eight seats. Start with four, add the rest when you need them.

            

              Each role knows what it owns, what it must not do, how to hand off, and when to stop
              and ask you.
            

          

          

        

      


      

        

          

            crew doctor
            
A linter for your team setup.

            
Run it locally or in CI. It exits non-zero when the setup drifts.

            
    
              
  • Every agent file has valid frontmatter
    • 
              
  • Every role in AGENT_TEAM.md has an agent, and vice versa
    • 
              
  • Every source-of-truth document in CLAUDE.md exists
    • 
              
  • No tokens or keys hiding in agent prompts
    •
